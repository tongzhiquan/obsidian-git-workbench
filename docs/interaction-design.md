# Git Workbench 操作与导航取舍

日期：2026-10-19。

## 详情布局

结合当前插件以笔记编辑和少量历史追溯为主的定位，推荐图内展开作为下一阶段的默认详情布局。详情紧跟所选提交，提交、说明和变更文件形成一组，用户无需在列表与固定底部区域之间来回寻找。没有选择提交时可以把空间完整留给图。

底部停靠更适合连续审阅多个提交：图的位置稳定，长消息和文件树有各自的空间。但在 Obsidian 的笔记区、左右侧栏共同占用空间时，常驻上下分区会进一步压缩图的高度。这里是基于产品使用场景的判断，并非对用户频率的实测统计。

因此修正 2026-10-17 设计稿中“底部停靠默认”的建议。图内展开需要限高、支持详情内滚动，并维持左侧连线连续；不要照搬截图中占据大段空白的展开高度。首轮先做好一种默认布局，底部停靠可以作为后续偏好项。

## Obsidian 中的入口

保留一个 Git 工作台作为统一入口，通过工作台内导航进入提交图、文件历史等功能。不要给每一个模块创建独立系统窗口。

具体文件比较适合使用 Obsidian 原生标签：默认复用一个比较预览标签，用户需要长期并排查看时再固定或分屏。这样既能保留提交图的位置，也能沿用 Obsidian 的返回、标签切换和分屏习惯。原生标签页与独立系统窗口是不同层级；前一稿画出的外框用于表示工作区，并不要求另外创建操作系统窗口。

当前实现仍采用同一工作台的内部导航。本轮只落地功能清理，没有切换图布局或新增比较视图；上述结构属于后续实现建议。

参考：[Obsidian 官方标签页说明](https://help.obsidian.md/tabs)。

## 本轮落实的保存流程

可编辑比较遵循“编辑 → 未保存标记 → 保存到明确目标”：工作文件写入磁盘，暂存区写入待提交快照，历史版本只读。保存按钮位于比较工具栏，Ctrl/Cmd+S 等价。保存文件、暂存文件、创建 Git 提交继续是三个独立动作。

删除独立的草稿管理：没有“保存草稿”“放弃草稿”或重载后恢复草稿。编辑文本不再写入插件配置。当前会话内切换页面仍保留编辑器状态；需要重载插件或退出时，应先普通保存。工具栏的“重新加载文件”对未保存内容进行确认，避免误触直接丢弃。

移除“恢复备份”页面、命令和恢复副本接口，避免让用户同时理解 Git 历史、Stash 和另一套恢复系统。文件历史中的恢复指定版本属于明确的 Git 历史操作，继续保留；覆盖文件前的安全副本作为内部保护，不再作为一个独立导航模块。

升级保留旧数据与既有副本，不自动恢复旧编辑。自动提交、提交消息模板和 Stash 不属于此次删除范围。
